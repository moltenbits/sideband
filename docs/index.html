Sideband lets Claude Code and Codex work together, seamlessly. They share an append-only journal kept beside your project, and through it either agent can hand work to the other, ask a question, review a change, or divvy up the work and report back. Ask them to work together however you like, and each will prompt as necessary and awaken when something arrives.

Install

  1. Install the sideband CLI tool from the MoltenBits Homebrew tap, available for macOS or Linux. 
    brew tap moltenbits/tap
brew install sideband
  2. Set up the repository. This creates the sideband journal, installs skills and registers hooks for both agents, and prints what to do next. Rerunning it is safe, and sideband doctor reports the state at any time. 
    cd <your repository>
sideband init
  3. Let Claude Code accept pushes from Sideband, so entries arrive in its session directly instead of through a listener. In Claude Code this is /config, "Messages from your other sessions"; the same setting in your user settings is: 
    ~/.claude/settings.json
{ "crossSessionInbound": "accept" }
  4. In Codex, trust the hooks that init registered, and again whenever a later init reports one as added or updated. 
    /hooks

Use

Join from each session working on the repository. Claude Code joins with /sideband, Codex with $sideband. Then talk to either agent the way you always have: a prompt typed into Claude Code is for Claude, one typed into Codex is for Codex, and the prompt is journaled as your words. Ask one agent to bring in the other, and from there the two delegate to each other and reply on their own.

In Claude Code, give Claude the task and make Codex the reviewer, one commit at a time:

Fix #42, the upload retry loop. Keep the commits small and ask Codex to review each one before you start the next; address what it finds before moving on.

In Codex, give Codex the lead on a job for both of them, reviewing each other as they go:

Split the settings migration with Claude: you take the reader, Claude takes the writer. Agree the interface first, then review each other's commits as you both work along and tell me when it is done.

Everything you type on either side keeps being journaled, so a later prompt can redirect either agent. To reach the other agent without switching windows, start the prompt with @codex or @claude; @all speaks to both at once. sideband log prints the whole discussion as Markdown.

How it works

  • Agents delegate to each other and reply. Claude asks Codex to review a change, Codex asks Claude to explain a design, either reports status. Requests, replies, and status notes are journal entries of one shape, and a reply is correlated with the request it answers.
  • Every actionable chain traces to the human. An agent's request must link, through the requests and replies before it, to something the human asked, and the executable refuses one that does not. Within that, one agent may direct the other's work for as long as the human's request stands.
  • Delivery wakes the idle recipient in its existing conversation, without any model tokens spent waiting. Claude Code is reached over the inbox socket its own cross-session messaging uses; Codex is reached with codex queue into the thread it recorded when it joined.
  • The human is a participant, not a transport. Every prompt typed into either client is journaled verbatim and attributed to you. Each agent is spoken to in its own session; @codex at the start of a prompt typed into Claude Code routes it to Codex instead, and @claude does the reverse.
  • Nothing is lost, and nothing is tracked outside the journal. A request stays listed for its recipient until it has been answered, and for its sender until the reply exists; an acknowledgement only marks it as taken up. If several requests piled up while a client was away, it asks you which to take up rather than choosing one itself.
